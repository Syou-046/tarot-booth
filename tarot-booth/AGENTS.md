# AGENTS.md — 占い師のタロット

Claude Code と Codex が同じリポジトリを交互・並行に編集するための共通ルール。どちらのエージェントもこのファイルを最優先で守る。Claude Code 用の追記は `CLAUDE.md` にあるが、内容はここと矛盾させない。

## このプロジェクトは何か

映画『魔法使いちゃんは素直になれやしない』完成上映会(2026/10/17 土・新川あおやぎ公園)の占いブースで、スタッフがタブレットで運用するタロット占い。上映会のあとは同じコードを映画公式サイトに組み込む。仕様の中身は `docs/SPEC.md`、作業の順番と担当は `docs/ROADMAP.md`、決まったことの記録は `docs/DECISIONS.md` を読むこと。作業を始める前に必ずこの 3 つを読む。

## 役割

最終決定はしょう。Claude(Cowork)はルールと計画を書く。Claude Code と Codex は実装する。実装側が仕様を決めてはいけない。

## 絶対に守ること

参考サイトは waltzingmouse.com。流れ・機能・スプレッドはこのサイトに合わせる。サイトにない機能(独自スプレッド、演出の追加、解読文、占い結果の文章など)を「良かれと思って」足さない。

仕様が未決(`docs/SPEC.md` の「未決事項」)に関わる作業は実装しない。`docs/DECISIONS.md` の末尾に「提案」として選択肢と理由を書き、そこで止めてしょうに確認を求める。

カードの抽選は `src/deck.js` の `rand()` と `shuffle()` だけを使う。`crypto.getRandomValues` による一様乱数、非復元抽出、逆位置は 1 枚ごとに独立して 50%。`Math.random` は見た目の揺れ(シャッフル演出など)にだけ使ってよく、どのカードが出るかに影響させてはいけない。重み付け、シード固定、特定カードの除外や出やすさ調整は、しょうの決定なしに入れない。

解読文・カードの意味の文章を自分で書いて入れない。AI の API に接続しない(不採用が決定済み)。

## 技術上の制約

素の HTML / CSS / JavaScript。ビルド工程、フレームワーク、npm の実行時依存は入れない。スクリプトは ES modules ではなく通常の `<script>` を `deck.js → share.js → app.js` の順で読む(グローバル共有)。ファイルを増やすときもこの方式に合わせ、`index.html` の読み込み順を更新する。

ブースでは会場のネット環境に頼らず動くことが前提。外部 CDN・外部 API・外部画像を使わない。Google Fonts は読めなくても崩れないようフォールバックを必ず残す。

カード画像は `assets/cards/00.webp`〜`77.webp`。番号は 0〜21 が大アルカナ、22〜35 ワンド、36〜49 カップ、50〜63 ソード、64〜77 ペンタクル(各スートはエース〜10、ペイジ、ナイト、クイーン、キングの順)。この番号は結果 URL に使っているので変えない。

結果 URL の形式は `?n=3&cards=29r-62-1r`(`n` は本体の枚数、`r` は逆位置、`n` を超えた分は補足カード)。`?booth=1` は無操作 90 秒で最初に戻るブースモード。形式を変える場合は旧形式も読めるようにする。

画面の文言は日本語。来場者は地域の家族と子どもなので、ひらがなを多めにし、難しい漢字にはふりがなを付ける。コード・コミットメッセージ・ブランチ名は英語。ドキュメントは日本語。

## 共同編集の進め方

着手前に `docs/ROADMAP.md` の該当タスクの担当欄に自分の名前(`claude` か `codex`)を書き、その変更だけを先にコミットする。他方が担当中のタスクや、担当中タスクの「触るファイル」に書かれたファイルは編集しない。

1 タスク 1 ブランチ。ブランチ名は `claude/<タスクID>` または `codex/<タスクID>`(例 `codex/P2-1`)。`main` へ直接 push しない。

PR は相手のエージェントがレビューする。Claude Code の PR は Codex が、Codex の PR は Claude Code が見る。レビューでは「SPEC と合っているか」「抽選ルールを破っていないか」「関係ないファイルを変えていないか」を必ず確認する。

PR の説明には、何を変えたか、なぜか、どう確認したか(下の完了条件のどれを実行したか)、画面が変わる場合はタブレット幅とスマホ幅のスクリーンショットを書く。

関係ない整形・リネーム・リファクタリングを混ぜない。必要だと思ったら別タスクとして ROADMAP に提案する。

## 完了条件

ローカルサーバーで開いて確認する(`file://` では結果画像の保存が動かない)。例: `npx serve . -l 4173` または `python3 -m http.server 4173`。

- `node tests/smoke.mjs` が `OK` になる(Playwright が必要)
- タブレット横 1180×820 とスマホ 390×780 で、枚数選択 → シャッフル → 選択 → めくる → 補足カード → 画像保存 → 新しく占う、が最後まで操作できる
- ブラウザのコンソールにエラーが出ない
- 結果 URL を別タブで開くと同じ結果が出る
- `?booth=1` で無操作時に最初へ戻る
- OS の「視差効果を減らす」設定でも操作が止まらない
- ネットワークを切っても表示と操作が変わらない(P2 以降は必須)
